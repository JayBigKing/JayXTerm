# JayXTerm · Windows 初版

一个以 Windows x64 为目标的 SSH / SFTP 桌面客户端。MIT 许可，允许商业使用；不需要账号、云服务或 GPU 加速。已生成 Windows x64 便携版 EXE；当前版本为功能原型，尚待 Windows 实机验收。

## 0.5.4 分屏目录同步

「SSH 当前目录」以当前分屏的活动标签为准。Bash 和 Zsh 首次确认后会在连接中继续报告目录。Shell 自带目录报告时可直接同步，其他 Shell 仍可手动确认并查询一次。

## 0.5.3 分屏文件空间

点击「文件空间」后，现有的一到四个分屏直接显示各自当前会话的远程文件。可以继续切换标签、增加分屏、编辑文件，或将文件和目录拖到其他分屏和窗口。点击「返回终端」即可回到原来的 SSH 会话，文件目录与侧栏同步。

## 0.5.0 远程文件编辑

双击左侧普通文件会打开独立编辑窗口，点击行末的 ↓ 下载。多个文件可以并排编辑，重复打开同一文件会聚焦原窗口。编辑器支持代码缩略图、行号、常见语言高亮、查找替换与 Ctrl+S 保存。

支持 2 MiB 以内的 UTF-8 和 GBK 文本。底部编码菜单可以按指定编码重新读取，或将修改按选定编码保存。保存保留换行格式、所有者及标准权限位，同编码保存保留 UTF-8 BOM。保存前检查远端是否已被修改。保存需要同目录的创建权限，以及 SFTP 服务端允许替换已有文件。

## 0.4.1 分屏标签栏

每格顶部只显示本格的终端标签。点击标签或在本格使用 Ctrl+PageUp / PageDown 即可切换，左侧 SFTP 显示当前会话。可把标签拖到另一格的标签栏或终端区域。每个标签的 × 关闭该会话，分屏的「⋯」菜单可把整格标签合并到指定分屏，保留这些连接。

## 0.4.0 分屏和远程文件互传

- 点击「＋ 分屏」增加终端格，最多四格。把终端标签拖入目标格即可移动当前连接；点击分屏标题或终端，左侧 SFTP 跟随该连接。可以通过分屏菜单合并该分屏。
- 点击「双栏文件」，左右两栏分别选择当前窗口中已连接的会话，也可用同一会话浏览两个目录。点击「返回终端」恢复分屏。两个窗口的 SFTP 面板也可互相拖放。
- 拖动文件或目录到目标目录行，或拖到列表空白处复制到当前目录。支持嵌套、空目录与二进制文件。遇到同名目标报错，防止覆盖。
- 数据通过本机后台的两个 SFTP 连接分块中转，使用流的背压控制缓冲。两端连接需保持打开，已有 SSH 终端可继续使用。复制目录时发生错误，先前已完成的项目会保留。

## 0.3.4 简化 SSH 目录同步

已有 Shell 目录报告时，点击「SSH 当前目录」直接同步。否则，在空白 Shell 提示符点击「执行并同步」，应用通过当前 SSH 终端读取一次目录。支持 Bash 等常见 Unix Shell，无需编辑启动脚本。请在服务器正在运行命令或打开交互程序时先回到 Shell 提示符。

## 0.3.3 SFTP 与帮助菜单

- 拖到子目录时，只高亮目标目录行。拖到空白处或普通文件行时，高亮列表并上传到当前目录。
- 通过「上传」菜单选择本地文件或文件夹。下载入口位于每行右侧。
- 点击「SSH 当前目录」跳到 Shell 最近一次通过 OSC 7 报告的目录。尚未收到报告时，应用会显示 Bash 配置方法。底部「帮助」菜单包含目录同步与 Vim 编码说明。

## 0.3.2 系统剪贴板（仅右键菜单）

- 鼠标选中终端文字，右键选择“复制”；从其他软件复制后，在终端右键选择“粘贴”。菜单也提供“全选终端文本”。
- 按用户偏好移除复制、粘贴快捷键及菜单快捷键提示；终端内阻止浏览器原生剪贴板事件，只有右键菜单访问系统剪贴板。Ctrl+C 保留中断，Ctrl+V 保留终端原始控制键（例如 Vim 的可视块模式）。应用中的普通表单输入框不受影响。
- 粘贴仍经过 xterm paste API，保留 bracketed paste 和当前会话 UTF-8 / GBK 输入编码，不重复发送。不轮询剪贴板。

## 0.3.0 多窗口（性能优先）

- 顶部“新窗口”或 `Ctrl+Shift+N`：新建独立工作窗口。所有窗口共享会话配置，各自打开和管理终端。
- “移出标签”：把当前已连接标签移到新窗口。右键标签可移到新窗口或已有窗口。
- 顶部“窗口”或 `Ctrl+Shift+O`：查看窗口、切换窗口，将当前标签移到指定窗口。`Ctrl+PageUp / PageDown` 切换当前窗口的标签。
- 移动保持同一 SSH 连接，保留终端历史、光标和模式、GBK 编码及 SFTP 当前目录；支持正在运行的 Vim。移动后更新远端 PTY 尺寸。
- 关闭窗口会提示断开本窗口的连接，不关闭其他窗口的连接。移动中暂时阻止关闭参与交接的窗口。
- 文件传输、目录读取或连接未完成时暂不移动；目标恢复失败会回退到原窗口。再次运行程序会在现有应用进程中打开新窗口。

性能设计：终端输出仅发给所属窗口；不镜像终端、不广播输出、不轮询窗口和会话状态。只有用户主动移动时才按需加载约 15.5 KB 的序列化模块并进行一次状态转移；不会持续序列化。终端历史仍为 3000 行，单次移动状态上限为 4 MiB，过大时拒绝移动并保留原连接。新窗口仍有 Electron 界面的内存开销，本版不宣称零开销。

暂未做窗口内分屏、拖出动画、跨窗口原生拖放或退出后自动重连恢复，避免把复杂状态同步引入当前输入路径。

## 0.2.0 新增

- 编辑会话时可点击密码右侧“显示 / 隐藏”；已保存密码仅在明确点击后解密给编辑框，关闭编辑框清空。未加入额外登录或主密码。
- 新建 / 编辑会话可点击“测试连接”，无需先保存，分别验证 SSH 密码认证与 SFTP 子系统，不创建交互终端；仍保留服务器指纹确认。
- 新建 / 编辑会话可保存 UTF-8 或 GBK / CP936 默认编码，已有连接可在底部切换，并保存为该会话下次连接的默认值。编码独立于其他已打开标签；输入和输出均转换，GBK 解码保留跨包字符状态。SFTP 不转换文件字节。

### GBK 文件与 Vim

终端编码、Vim 内部编码、文件编码是三个独立设置。`cat` 直接输出文件字节；Vim 会读取文件后按自己的终端编码输出。因此，cat 正常而 Vim 乱码可以由终端编码不匹配引起，不能只根据文件是 GBK 推断终端也必须选 GBK。

终端选 GBK / CP936 时，在 Vim 中设置：

```vim
:set encoding=utf-8 termencoding=cp936
```

终端选 UTF-8 时，Vim 的 `termencoding` 应为 `utf-8`（内部 encoding=utf-8 时通常也可为空）。GBK 文件误判时，确认无未保存修改后用 `:edit ++enc=gbk` 重新读取。保存现有 GBK 文件时保留 `fileencoding=cp936` 或 `gbk`，避免无意改写成 UTF-8。底部“Vim 编码帮助”也包含这些操作。

客户端不会自动向正在运行的远程程序注入设置命令，不会修改服务器的 locale 或 vimrc。切换只影响后续输出，不重新解码历史缓冲；可在 Shell / Vim 中按 Ctrl+L 重绘。

已用真实 Vim 验证：GBK cat、错配终端编码的乱码复现、GBK Vim 中文显示和输入、保存后仍为 GBK，以及 UTF-8 终端中用 Vim 读取 GBK 文件。依据：[Vim termencoding 文档](https://vimhelp.org/options.txt.html#%27termencoding%27)。

## 0.1.1 修复

修复连接建立期间终端尺寸更新丢失的问题：SSH 握手前缓存最新行列数，Shell 建立后补发；界面在连接完成时也主动同步当前尺寸，即使窗口没有发生变化。解决由远端列数与实际终端不一致引起的长命令换行覆盖和历史命令重绘错位。

## 已实现

- SSH 密码认证、交互式终端、多个连接标签和窗口尺寸同步。
- 保存、编辑、删除会话，按分组显示，按名称 / 地址 / 用户 / 分组搜索。
- 可选保存密码：Windows 使用 Electron safeStorage / DPAPI 加密；会话列表不把已保存密码返回给界面。
- 首次连接显示 SHA-256 主机指纹，需要确认；指纹变化时再次警告，不静默接受。
- 左侧 SFTP 目录浏览、手动切换路径、文件 / 整目录上传下载与传输进度；支持将本地文件、文件夹拖入左侧面板上传，也可拖到某个远程文件夹上。上传遇到同名目标时确认覆盖或合并。
- 独立 SSH / SFTP 后台进程，终端输出设置高低水位流量控制；键盘输入直接转发，不做定时节流。
- 默认关闭硬件加速，不加载 WebGL 插件，作为无 GPU 环境的验收基线。

## 直接运行便携版

已生成的程序：`.codex-cache/releases/JayXTerm-0.5.4-x64-portable.exe`。将 EXE 复制到 Windows 电脑后运行，无需 Node.js。当前为未签名版本，Windows 实机尚未验收，验证情况见 `VERIFICATION.md`。

## 在 Windows 启动

开发工具需要 Node.js 22.12+（建议 Node.js 22 LTS）。在项目根目录打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/windows.ps1 install
powershell -ExecutionPolicy Bypass -File scripts/windows.ps1 dev
```

脚本只对当前进程设置缓存环境变量，临时文件、npm / Electron / 打包缓存都放在项目 `.codex-cache` 下。首次安装和打包需要联网下载依赖；打包后的应用可直接在内网使用，无需安装 Node.js。

## 生成 Windows x64 安装包与便携版

**请在 Windows 上运行打包**：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/windows.ps1 package
```

输出位于 `.codex-cache/releases/`，包括 NSIS 安装包和 portable EXE。当前没有代码签名证书，Windows 可能提示未知发布者。支持 Windows 10 / 11 x64；未覆盖 Windows 7、32 位或 ARM64。

仓库内包含 `.github/workflows/windows.yml`：在 Windows runner 上执行依赖安装、真实 SSH/SFTP 测试、Electron 启动与密码存储检查，生成 EXE 并上传构建产物。此工作流尚未在本地环境触发执行。

## 使用

1. 点击“新建会话”，填写名称、IP、端口、用户名和密码。
2. 可选择在本机加密保存密码；不保存则每次连接时输入。
3. 双击会话或点击 ↗ 连接，核对服务器指纹后确认。
4. 连接后左侧自动显示远程文件，右侧显示终端。双击文件夹进入，双击普通文件编辑，点击行尾的 ↓ 下载。下载目录时选择本地目标文件夹。上传可通过「上传」菜单，也可直接拖入左侧面板。左上角可随时切回会话列表。
5. 编辑会话时，密码留空保留已保存密码；取消勾选保存则从磁盘移除密码。关闭标签会断开连接，删除保存的会话不会关闭已经打开的连接。

开发模式配置保存在 `.codex-cache/profile/`，安装版位于 Windows `%APPDATA%/JayXTerm/`（实际应用名称以 Electron userData 为准）。密码密文绑定系统用户，复制配置到另一台电脑或用户后通常无法解密。DPAPI 不能防止同一 Windows 用户权限下的恶意程序访问凭据。尚未另设主密码；已保存密码可由当前应用中的“显示”按钮查看。

## 初版边界

目前支持密码认证；未实现私钥 / MFA、跳板机、代理、凭据共享库、会话导入导出、远程编辑器、断点续传与传输取消。单个标签一次执行一个传输批次；目录递归传输保留空目录，不跟随符号链接。下载遇到 Windows 不支持的文件名或同目录大小写冲突时报告错误。已完成的文件在失败后保留；传输不会自动回滚。目录浏览操作超时为 30 秒，传输持续到完成或连接断开。没有后台更新或遥测。
